# Group Proposals and Voting Runbook

GT-03A provides the decision-evidence foundation for group governance. A paid active member may create a draft proposal against the group's effective constitution. A governance manager opens it only during its configured window, which atomically freezes eligible voters, direct conflict exclusions, quorum, approval threshold, approval rule, and whether vote changes are allowed. Later membership changes never alter that snapshot.

Votes are append-only. When the constitution permits changes, a new ballot supersedes the prior ballot without deleting history; otherwise the first ballot is final. Ordinary decisions require quorum and more approvals than rejections. Constitution amendments, closure, suspension, expulsion, and treasury decisions use integer-ceiling eligible-voter thresholds of at least two thirds. Abstentions count toward quorum but not ordinary approval. A proposal closed without quorum expires. Approved proposals do not directly mutate another domain; an approved, idempotent execution adapter must perform that work in a later increment.

Read APIs expose public summaries, schedule, immutable threshold evidence, aggregate tallies, and results to active group members or authorized tenant auditors. Private evidence references, execution payloads, and conflict identifiers are returned only to governance managers. Ballot identities are not exposed by the public read model. Cross-tenant and inaccessible resources receive neutral not-found responses.

If opening fails, correct the draft or its schedule and retry with a new idempotency key and current version. If a ballot command times out, retry the identical command with the same key. If closing fails, verify the close time, expected version, and manager authority; do not edit snapshot or ballot rows. Draft or open proposals may be cancelled with an evidenced reason. Once decided, preserve all records and use a new corrective proposal. During an incident, disable `groups.governance.manage` to stop new API commands while retaining evidence and investigating through service-role read access. Never delete or rewrite proposals, snapshots, ballots, or events after live use.
